# 공통 규칙

## URL과 버전

- 공개 API: `/api/v1`
- 내부 추론 API: `/internal/v1`
- 리소스명은 복수형과 kebab-case를 사용합니다.

## 인증과 권한

- 공개 API: `Authorization: Bearer <access_token>`
- 내부 추론 API: `X-Internal-API-Key`
- Flutter와 React는 내부 추론 API를 직접 호출하지 않습니다.
- 환자는 자신의 데이터만 조회할 수 있습니다.
- 의료진은 담당 또는 권한이 있는 환자 데이터만 조회합니다.
- 관리자 권한은 운영상 필요한 범위로 제한합니다.

## 날짜와 시간

- 날짜: `YYYY-MM-DD`
- 시간: ISO 8601 + timezone
- 예시: `2026-08-05T10:30:00+09:00`
- 서버 저장은 UTC를 사용할 수 있지만 API 반환에는 timezone을 명확히 포함합니다.

## 성공 응답

```json
{
  "data": {
    "patient_id": "uuid",
    "name": "김환자"
  }
}
```

## 목록 응답

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "page_size": 20,
    "total_count": 0,
    "total_pages": 0
  }
}
```

## 오류 응답

```json
{
  "error": {
    "code": "PATIENT_NOT_FOUND",
    "message": "환자를 찾을 수 없습니다.",
    "details": {
      "patient_id": "uuid"
    }
  }
}
```

## 권장 HTTP 상태 코드

| 상태 | 용도 |
|---|---|
| 200 | 조회·수정 성공 |
| 201 | 리소스 생성 |
| 202 | 비동기 Job 접수 |
| 204 | 삭제 성공, 응답 본문 없음 |
| 400 | 형식·입력값 오류 |
| 401 | 로그인 또는 토큰 오류 |
| 403 | 역할·데이터 접근 권한 없음 |
| 404 | 리소스 없음 |
| 409 | 중복, 상태 전이 불가, 이미 처리됨 |
| 422 | 필드 단위 검증 실패 |
| 500 | 서버 내부 오류 |

## 멱등성

- 추론 Job은 `job_id`를 멱등성 키로 사용합니다.
- 같은 복약 일정에 대한 중복 기록은 `409` 또는 기존 레코드 반환 중 한 가지 정책으로 통일합니다.
- FCM 토큰 등록은 동일 토큰이면 새 레코드를 만들지 않고 갱신합니다.
